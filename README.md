# Gaia data inventory

Public geospatial datasets for linking place to health, assessed for [Gaia](https://github.com/OHDSI/gaiaDB) (OHDSI GIS working group). Each dataset carries checks (link, licence, years, spatial unit, access, place key, format) with the evidence URL behind every value. This is a list of **prospective** sources: only rows marked `in_gaia` are in the Gaia catalog so far.

## Contribute

You need Claude Code, Python, the GitHub CLI (`gh`, signed in) and push access to this repo (ask Robert). There is one queue of open work; you choose what and how much to take.

1. **Clone and start Claude Code** (Sonnet is enough):
   ```bash
   git clone https://github.com/rtmill/gaia-data-inventory && cd gaia-data-inventory
   git switch -c work/<your-handle>
   claude
   ```
2. **Type `/inventory`.** Claude shows the queue: each kind of work, how many items are open, and what one item costs in minutes and tokens (from earlier runs). Tell it which kind and how much you want: a number of items, or a time or token budget. You can narrow by region, topic, publisher or site.
3. **Claim it.** When you agree to the list, Claude opens a GitHub issue titled `[claim] …`, assigned to you, listing your items. That is the claim: those items are hidden from everyone else until the issue closes.
4. **Claude does the work** and writes one file under `ledger/`.
5. **Open a pull request** with `Closes #<your claim issue>` (Claude offers to do this). Checks run automatically; when they're green, merge it. The inventory rebuilds itself, your claim closes, and anything you didn't finish goes back to the queue.

Just looking, without Claude: `python scripts/queue.py` (add `--help` for slicing and claiming by hand). More detail, the rules, and what to do if a check fails: [CONTRIBUTING.md](CONTRIBUTING.md). Suggesting a dataset without any of this: [open an issue](../../issues/new?template=suggest-dataset.yml).

## How it works

```
base/inventory-base.csv   the inventory as of 2026-11-18 (frozen)
        + ledger/*.jsonl   every change since, one file per contribution, applied in file-name order
        = build/           the current inventory, queues and site data (generated by CI; never edited by hand)
```

- **Nobody edits the CSVs.** A contribution is a ledger file of small change records, each with the URL it was read from. `scripts/build.py` replays base + ledger, recomputes tiers and the work queue, and CI commits the result.
- **Tiers.** Gold: link, page, licence, unit, years and access all pass. Silver: live, read, and no fail among licence, unit, years, recency. Bronze: live, not fully read. Browser needed: the site blocks scripts. Failed: dead, withdrawn, or data before 2000. Rules in `scripts/inv.py` (`tier_of`).
- **Method and history** are in `method/`: the page-read brief, unit vocabulary, anchors (what we measure coverage against), the TODO, and every iteration that built the inventory (`method/iterations/`).

| Folder | What it is |
|---|---|
| `build/inventory-verified.csv` | Gold and Silver, readable columns |
| `build/inventory-all.csv` | Every dataset, every check, detail and evidence |
| `build/queue.csv` | Every open item of work (`python scripts/queue.py` slices it, estimates it and claims from it) |
| `ledger/` | Contributions (append-only) |
| `base/` | The frozen starting point and the candidate families still to check |
| `method/` | How it was built and how to work on it |
| `site/` | Source of the GIS site's Data Inventory page |
